# صاحب النادي — 0.20.0 · Club Owner

نسخة ويب عربية أولية قابلة للعب، مصممة لويندوز وشاشات الآيفون. المشروع **مقسم إلى ملفات وأنظمة مستقلة**، وليس ملف HTML/JavaScript واحدًا.

## تنبيه البيانات والنطاق

- أسماء الأندية حقيقية للاختيار فقط؛ الشعارات رسم حرفي تجريبي وليست الشعارات الرسمية.
- القاعدة العالمية الافتراضية: 23,463 اسمًا مستوردًا عبر 50 سوقًا، من 819 صفحة نادٍ لها أسماء مستوردة (14 منها من نسخة لغوية أخرى لويكيبيديا، و262 صفحة تشكيلة عربية/فرنسية/إسبانية قُرئت لاستكمال تواريخ الميلاد في 0.18b). 5 صفحات أخرى بلا قائمة مستوردة، و4,272 اسمًا بلا تاريخ ميلاد موثق (عمر تقديري موسوم «~»). Wikipedia CC BY-SA + Wikidata/openfootball CC0. حزمة 0.2 القديمة (86 اسمًا أوليًا) والعالم الخيالي ما زالا خيارين منفصلين.
- النمط القديم يحتفظ بالدوري المصغّر. النمط الموسع يشغّل 116 مسابقة دوري، منها 66 مسابقة أقل تضم 1072 ناديًا في 47 سوقًا، بصعود وكؤوس مبسطة؛ أوروبا الجديدة تضم مرحلة دوري وملحقًا وذهابًا وإيابًا. قوائم الدخول والمعاملات والتواريخ ليست رسمية.
- لا إعلانات حقيقية، ولا مدفوعات، ولا حسابات مالية حقيقية، ولا اتصالات بخدمة خارجية عند اللعب.
- العالم الموسع يضم محاكاة خفيفة بالخلفية، انتقالات محدودة وإعارة تطويرية وتشكيلًا أوليًا. لا مباريات مرئية ولا محاكاة كاملة للوائح أو اقتصاد كل بلد.
- قاعة الأساطير تستخدم أسماء حقيقية لأساطير معتزلة؛ الذروة والسمات والأسعار والرواتب وردود القبول تقديرات تحريرية للعبة وليست بيانات رسمية. «عودة كلاعب» وضع خيالي اختياري ومعلن.

## التشغيل على ويندوز

1. ثبّت **Node.js 20.19+ أو إصدار LTS أحدث**.
2. فك ضغط المشروع وافتح Terminal داخل `FootballClubManager`.
3. نفذ:

```sh
npm ci
npm run dev -- --port 5173
```

أو استخدم `start-windows.bat` بعد تثبيت Node.js. المتصفح على الكمبيوتر يفتح العنوان المحلي الذي يظهر في الطرفية.

### فتحه على الآيفون من نفس الشبكة

مع بقاء الكمبيوتر يعمل والخادم مفتوحًا: افتح في Safari عنوان IP المحلي **للكمبيوتر** متبوعًا بـ `:5173`، مثل `http://192.168.1.20:5173` (هذا مثال، وليس عنوان جهازك). لا تستخدم `localhost` على الهاتف لأنه يشير للهاتف نفسه. قد تحتاج السماح لـNode.js عبر جدار حماية ويندوز على الشبكات الخاصة فقط.

رابط المعاينة أثناء جلسة التطوير يُفتح مباشرة دون الخطوات السابقة، لكنه ليس استضافة دائمة. إعداد Vite الحالي يقبل مضيف المعاينة؛ لا تستخدم خادم التطوير على شبكة عامة كاستضافة إنتاجية.

## بناء نسخة استضافة ثابتة

```sh
npm run build
```

ينتج مجلد `dist`. يمكن استضافته لاحقًا على HTTPS. يوجد نشر سابق يديره المالك على Cloudflare Workers؛ تعديل المصدر هنا لا يحدّثه تلقائيًا. لم يُعدّ دخول خاص. من الإصدار 0.1.1: نسخة الإنتاج تتضمن manifest وأيقونات وService Worker للعمل دون اتصال بعد تجهيزها أول مرة. تضاف من Safari إلى الشاشة الرئيسية، لكنها ليست تطبيق App Store. يلزم HTTPS (أو localhost للاختبار)، ويجب فتحها مرة بنجاح وتحميل مواردها. الحفظ المحلي ليس نسخة احتياطية مضمونة؛ نظام iOS قد يحذف بيانات الموقع.

## جولة اختبار قصيرة

1. اختر ناديًا، واكتب اسم المالك واختر أسواق اللاعبين.
2. افتح سوق الانتقالات، اختر لاعبًا، وحدد الرسوم والمقدم. مرّر يومًا.
3. وافق أو ارفض رد النادي في البريد. بعد الاتفاق، تفاوض على مرتب اللاعب ومدة العقد والمكافأة والدور.
4. افتح الرعايات، اختر مساحة متاحة، وراجع العرض والحصرية قبل التوقيع.
5. ابدأ مشروع منشأة. يتخصم ٤٠٪ الآن، و٦٠٪ عند الاستلام. عيّن الموظف المطلوب لتفعيل الأثر الرياضي.
6. مرّر أسبوعًا. تتوقف المحاكاة عند أول قرار إلزامي، وتحتفظ بالأيام المتبقية. القراءة وحدها لا تحسم القرار.
7. راجع السجل المالي: الدفعات والحركات موحّدة ولا تُسجّل مرتين.
8. في الإعدادات، صدّر حفظة احتياطية.

## الحفظ

- حفظة واحدة نشطة لكل متصفح ولكل أصل رابط (origin).
- القاعدة العالمية تحفظ في IndexedDB بلقطات ثابتة؛ localStorage يحمل مؤشر الحالية والسابقة. الحزم الصغيرة تبقى في localStorage. حد الاستيراد 80 MiB. تصدير العالم الكامل قرابة 61 MB للعالم الموسع، فاحفظ مساحة كافية.
- كل تعديل يطبّق على نسخة من الحالة؛ يتم التحقق من سلامتها وحفظها قبل اعتمادها في الواجهة.
- الاستيراد يتحقق من الإصدار، الأرقام، كشف الحساب، الهويات، والعلاقات الأساسية قبل الاستبدال.
- لا يوجد حفظ سحابي أو مزامنة بين الأجهزة. لنقل التقدم من الكمبيوتر للهاتف، صدّر الملف ثم استورده على الهاتف.
- مسح بيانات الموقع أو تغيير عنوان الرابط قد يفقد الوصول للحفظة. التصدير مهم خصوصًا مع روابط المعاينة المؤقتة.
- صيغة الحفظ الحالية v4؛ ترحيل v1/v2/v3 يحافظ على اللاعبين القدامى، ولا يحول الحفظة تلقائيًا إلى قاعدة العالم. احتفظ بنسخة JSON قديمة مستقلة قبل تحديث أو الرجوع للإصدار السابق.

npm run i18n:coverage        # الماسح الساكن للعبارات بلا ترجمة

SEASONS=10 OUT=capacity.json node --max-old-space-size=1400 tests/capacity-baseline.mjs   # تعداد اللاعبين والأرشيف وحجم الحفظة وزمن اليوم لكل موسم

تم اختبار Chromium على الكمبيوتر ومحاكاة شاشة 390×844، وWebKit بمحاكاة هاتف. هذا **ليس** اختبارًا على جهاز iPhone فعلي؛ تجربتك على Safari هي الخطوة التالية. اختبارات المتصفح تنشئ صور مراجعة داخل `review/`.

## خريطة المراحل التالية

1. مصدر بيانات مرخّص/مسموح وقابل للتحديث، منفصل عن حالة الحفظة؛ توضيح المنهج التقديري للقدرات.
2. حزم دول ومسابقات وقواعد تسجيل، ومستويات محاكاة متعددة مع قياس أداء فعلي.
3. نقل المخزون الكبير من localStorage إلى IndexedDB، وتطوير ترحيل الحفظ ونسخ احتياطية متعددة.
4. توسيع العقود: الإعارات وعروض شراء المنافسين، ووعود أكثر تفصيلًا، وتجديد الرعايات قبل الانتهاء.
5. بناء المنشآت بمراحل وتأخير وتعاقدات أكثر تفصيلًا؛ صيانة وجودة وسعة منفصلة.
6. ذكاء الأندية والأجهزة الفنية، تكتيكات وتدريب وإصابات، وتوسيع المسابقات المتتابعة.
7. حفظ سحابي ومصادقة عند الحاجة، ثم توسيع اختبارات PWA وتجهيز استضافة دائمة.

الخط المستخدم: Cairo محلي، بترخيص SIL OFL داخل `public/fonts/Cairo-OFL.txt`، مع الاحتفاظ بخط Noto Sans Arabic القديم وترخيصه. جميع الأيقونات ورسمة الملعب SVG محلية؛ لا تعتمد اللعبة على CDN.

## نسخة جاهزة للرفع على الاستضافة (0.2.0)

`club-owner-v0.2-ready-to-upload.zip` حزمة الإنتاج الجديدة، مختلفة عن المصدر. فكّها وارفع **محتويات مجلد `ClubOwner-Upload-v0.2`**، حيث `index.html` في جذر الموقع. لا ترفع ملف ZIP المصدر، ولا مجلد الغلاف الذي يحتوي الدليل. لا تحتاج نسخة الرفع npm أو تشغيل الكمبيوتر بعد النشر؛ المصدر يظل مقسمًا داخل `src/`.

### تحديث مشروع Cloudflare Workers القائم

المشروع المستخدم هو **green-grass-b2ad**، والرابط المعروف: https://green-grass-b2ad.amrg5191.workers.dev/ . لم ينشر المساعد التحديث تلقائيًا ولم يتحقق من إصداره على الرابط.

1. صدّر JSON من اللعبة الحالية قبل تغيير الإصدار.
2. في لوحة Cloudflare افتح Workers & Pages ثم مشروع Workers نفسه. استخدم خيار نشر/رفع نسخة جديدة للملفات الثابتة، وفق واجهة حسابك.
3. ارفع ملفات مجلد الإنتاج الجديد مع وجود `index.html` في الجذر، ثم أكد النشر. إذا اختلفت الشاشة، راجعها قبل إنشاء مشروع جديد أو تغيير النطاق.
4. افتح **نفس الرابط**؛ وافق على تحديث اللعبة عند ظهور الإشعار، أو أغلقها وافتحها مجددًا. تحقق من إصدار 0.2 في الإعدادات وظهور اختيار الصعوبة عند إنشاء حفظة.
5. لا تمسح بيانات Safari. ترحيل v1 إلى v2 اختُبر، لكن احتفظ بنسخة قديمة منفصلة للرجوع. الأسماء الجديدة تحتاج حفظة جديدة.

الموقع عام ما لم تُضبط حماية دخول حقيقية. `noindex` و`robots.txt` ليسا حماية، ولا تم التحقق من حماية خاصة أو تفعيلها هنا. iOS قد يحذف بيانات التخزين؛ التصدير الدوري مهم.

### اختبار العمل دون اتصال

شغّل نسخة الإنتاج (`npm run build` ثم `npm run preview -- --port 5173`) وبعدها `npm run test:offline`. الاختبار يفتح حفظة، ينتظر تجهيز Service Worker، يقطع الشبكة، يعيد التحميل ويكمل صفقة، ثم يعيد فتح اللعبة من تبويب جديد ويتحقق من الحفظ. لا يعني هذا اختبار جهاز iPhone فعلي.
